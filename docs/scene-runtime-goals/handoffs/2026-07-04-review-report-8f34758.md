## 8f34758 核心改动摘要

本次 commit 主要解决 **early copy 与 scene host 的耦合问题**，以及 **转场期间 target scene 的可见性**。

### 1. Early Copy 从 Scene Host 中拆分（`SceneRuntimeDomShell.js`）

新增 `EARLY_COPY_SELECTORS` 和 `cloneEarlyCopy()`：

```js
const EARLY_COPY_SELECTORS = Object.freeze({
  'method-top': Object.freeze(['.edition-vertical-lead', '.chapter-intro']),
  'services': Object.freeze(['.enterprise-vertical-lead', '.chapter-intro']),
  'contact': Object.freeze(['.contact-endpoint'])
});
```

`projectRevealLayer()` 不再显示整个 scene host，而是**只克隆指定的文字 DOM 元素**到 `early-copy` 层（z-index: 4），并**主动移除所有背景元素**（canvas, video, img, svg, ol, ul, button, .btn, .text-link, .method-flow, .method-brief, .edition-row-list, .enterprise-capability-list, .contact-actions）。

### 2. 转场期间 Target Scene 变为 Preview（`applyProjection`）

新增 `transitionTargetId()` 检测：当 `activeAttempt` 的 `kind` 为 `transition`/`scene-play-transition`/`read-transition` 且 `state` 为 `SNAP_LOCKING`/`TRANSITIONING` 时，将 `attempt.to` 标记为 `preview`：

```js
host.hidden = !isVisible;                    // isVisible = stable || preview
host.setAttribute('data-scene-visible', isStableVisible ? 'true' : isTargetPreview ? 'preview' : 'false');
host.setAttribute('data-scene-role', sceneId === projection.current ? 'stable' : isTargetPreview ? 'target-poster' : 'hidden');
```

同时 `projectTargetLayer()` 将 target host 移动到 `target` 层（z-index: 2），并应用 `clip-path: inset(var(--runtime-transition-reveal-inset, 100%) 0 0 0)`。

### 3. Shell 样式强化

- `[data-scene-runtime-shell]` 新增 `min-height: 100vh` / `min-height: 100dvh`
- `[data-scene-id]` 新增 `min-height: 100vh` / `min-height: 100dvh`
- `[data-scene-id="contact"][data-scene-role="stable"]` 强制 `background: #eee5ce !important`（亮色）
- `[data-scene-id="services"][data-scene-role="stable"]` 强制 `background: #ede4d2 !important`（亮色）
- 对应文字颜色强制为 `#17251f`（深色）

### 4. 路由调整（`SceneRuntimeCore.js`）

- `star-map → aod`：`scene-play-transition` → `transition`（`bottom-to-top-ink`）
- `figure2-animation → brand`：`scene-play` → `scene-play-transition`（`bottom-to-top-ink`）
- `runScenePlayTransitionAttempt` 在 transition 完成后调用 `clearEarlyCopy('scene-play-transition-committed')`

### 5. `Presentation.js` 精简

`presentEarlyCopy` 不再将 `sceneId` 加入 `visible` 集合。early copy 的可见性完全由 `reveals` 驱动，由 `projectRevealLayer` 单独处理。

## 关键发现与风险

### 1. Starmap Poster 状态显示 Belief 文字（Finding 4 根因）

`StarmapScenePlayer.showPoster()`：

```js
this.setSourceVisible();
// ...
setSourceVisible() {
  if (this.copyWrap) {
    this.copyWrap.style.opacity = '';        // ← 恢复 CSS 默认 opacity = 1
    this.copyWrap.style.filter = '';
    this.copyWrap.style.transform = '';
  }
}
```

`buildSceneDom()` 创建的 `.belief-copy-wrap` 在 CSS 中无默认 `opacity` 限制（`canvas-stage.css` 和 `homepage-continuity.css` 中 `.belief-copy-wrap` 的 opacity 只在 `.is-pattern-bloom-pinned` 下受 CSS 变量控制）。

**后果**：在 `star-map → aod` 的整个 transition 期间，belief 文字始终完全可见（opacity=1），且不会被 clip-path 或 canvas 完全遮挡（curtain 类型的 canvas alpha < 1）。

**建议**：`showPoster()` 应显式将 `copyWrap.style.opacity = '0'` 或添加 `data-starmap-poster` 类来隐藏 belief 文字，仅在 `playForward` 时通过 progress 驱动显示。

### 2. Figure2 Proof 屏被 Ink 强制淡出（Finding 6 根因）

`figure2-compound-scene-player.js:813-822`：

```js
renderProof() {
  const reveal = smoothStep(this.proofProgress);
  const handoffFade = 1 - smoothStep(range01(this.inkProgress, 0.58, 0.9));
  const opacity = smoothStep(range01(reveal, 0.015, 0.16)) * handoffFade;
  // ...
}
```

当 `inkProgress = 0.94`（ink-sweep 步骤）：
- `handoffFade = 1 - smoothStep(range01(0.94, 0.58, 0.9)) ≈ 1 - 0.972 = 0.028`
- `opacity ≈ 0.028`

proof 屏在 ink-sweep 阶段几乎完全透明。然后 `present-brand`（progress=1）时 ink canvas 满屏白色。用户几乎无法看到 proof 屏内容。

**建议**：
- 方案 A：将 `inkProgress` 的 fade 区间后移（如 `0.75-0.95`），给 proof 屏更多显示时间
- 方案 B：将 figure2 的路由改回 `scene-play`（不带运行时 transition），让 figure2 内部的 `present-brand` 步骤直接完成 handoff
- 方案 C：在 `present-brand` 步骤后、运行时 transition 开始前，添加一个短暂的 hold 帧，让 proof 屏完全显示

### 3. Scene 类型过渡的 Handoff 仍非无缝（Findings 1, 2）

`center-ink-expand` 和 `left-rotate-bloom` 均为 `type: 'scene'` 过渡。`MvpInkTransitionPlayer` 的 `segmentOptions` 返回 `targetSrc` 为静态图片：

```js
center-ink-expand: { targetSrc: 'assets/patterns/backgrounds/aged-mottled-background-16x9-4k.png' }
left-rotate-bloom: { targetSrc: 'assets/back2.png' }
```

过渡 canvas 渲染的是**静态图片**，而非 target scene 的 live DOM。handoff 时 canvas 消失，target DOM 出现。即使 target DOM 已预置在 target 层，静态图与 DOM 之间的视觉差异仍会导致可感知的切换。

**建议**：将 `scene` 类型过渡改为 `curtain` 类型（如 `bottom-to-top-ink`），或让 `createInkSceneTransition` 直接渲染 target scene 的 DOM 快照（如 `html2canvas`），而非预定义静态图。

### 4. AOD 无视频 Dissolve 入场（Finding 3 根因）

`star-map → aod` 改为 `transition` 类型后，AOD 的入场流程：
1. `prepareTransitionTarget` 调用 `aodScenePlayer.showPoster()` → 设置 video currentTime = 0，progress = 0
2. 运行时 `bottom-to-top-ink` curtain 过渡覆盖 viewport
3. 过渡完成后 `presentation.present('aod-animation')`

AOD 内部的 `playForward`（视频播放 + 溶解动画）**永远不会被调用**。AOD 始终以 poster 状态（静止帧）入场。

**建议**：将 `star-map → aod` 改回 `scene-play-transition` 类型，或在 transition 完成后显式调用 `activateStableScene('aod-animation')` 来触发 AOD 的播放。

### 5. 运行时 Timeout 正确配置（已排除风险）

`scene-runtime-dom-entry.js`：

```js
createSceneRuntimeDomShell({
  timeouts: {
    transition: 2200,
    scene: 24000
  }
});
```

`SceneRuntimeCore` 的 timeout 最终为 `{ transition: 2200, scene: 24000, internalIntent: 120000 }`。transition 的 2200ms 足够覆盖 `MvpInkTransitionPlayer` 的 defaultDuration 520ms + 缓冲。所有 transition 和 scene play 不会因 timeout 提前中断。
