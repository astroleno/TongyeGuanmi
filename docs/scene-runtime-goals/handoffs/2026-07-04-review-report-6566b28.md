## 核心根因总结

**所有转场问题的共同根因：TransitionSegmentPlayer 是「空壳」过渡。**

在 `TransitionSegmentPlayer.js` 中：

```js
const SUPPORTED_SEGMENTS = new Set([
  'center-ink-expand', 'left-rotate-bloom', 'bottom-to-top-ink',
  'services-to-ttg', 'ttg-to-lab', 'lab-to-ph', 'ph-to-education', 'education-to-crane'
]);
```

`play()` 方法的核心逻辑（line 117-128）：
```js
await delay(Math.max(0, durationMs / 2));   // 默认 6ms
onProgress?.({ progress: 0.5, ... });
await delay(Math.max(0, durationMs / 2));   // 默认 6ms
onProgress?.({ progress: 1, ... });
emit('ended');
return { completed: true, segmentId, from, to };
```

**这意味着：**
- 所有 transition segment（center-ink-expand、left-rotate-bloom、bottom-to-top-ink 等）**没有任何 WebGL 或视觉渲染**，只是 12ms 的 setTimeout
- `Presentation.visible` 始终只包含**单一场景**（from），`to` 场景被 `host.hidden = true` 强制隐藏
- `TransitionSegmentPlayer` 太快了（12ms），状态从 `TRANSITIONING` 瞬间跳到 `PRESENTING`，`to` 场景的 target preview（`transitionTargetId`）只存在几毫秒
- `stableScenePlayers` 默认空数组，`activateStableScene` 对所有场景都是空操作，不会触发 `playForward`

**结果：用户看到的所有「转场」实际上都是瞬间切屏，没有过渡动画。**

## 逐条核实

### 1. hero → pattern，pattern 应该是展开状态，现在是闭合的 → 开闭开闪烁

**核实结果：✅ 成立（部分改善但根因未解）**

- `pattern-scene-player.js` 的 `showPoster` 将 `controlledProgress` 设为 `posterProgress = 1`（全开），`createScene` 的 `progressSource` 也指向 `controlledProgress`
- `TransitionSegmentPlayer` 对 `center-ink-expand` 只有 12ms delay，**没有 ink 动画**
- transition 完成后 `present('pattern')` 使 pattern 变为可见，但 `activateStableScene` 由于 `stableScenePlayers` 为空而不执行 `playForward`
- 所以 pattern 理论上应该保持 poster 状态（全开），但用户观察到的是**闭合 → 展开 → 闭合**的闪烁

**根因推断**：transition 期间 pattern 作为 `target` 被 `host.hidden = true` 隐藏。transition 完成后瞬间 visible，但 `createPatternMirrorScene` 的 canvas 在 hidden 期间可能未正确渲染，导致首次 visible 时出现一次「重绘/刷新」闪烁。加上 `host` 从 `source` 移动到 `target` 再移回 `source` 的 DOM 操作，视觉上产生开闭开抖动。

---

### 2. pattern → star-map，star-map 先出来又消失，被拉伸超过 100vh

**核实结果：✅ 成立（根因未解）**

- `left-rotate-bloom` 同样是 12ms delay 的空壳过渡
- `star-map` 的 `showPoster` 调用 `renderStableStarField()` 和 `startSteadyStarField()`，但 star-map 在 transition 期间作为 `target` 被 `host.hidden = true` 隐藏
- `SceneRuntimeDomShell.applyProjection` 中 `transitionTargetId` 只在 `SNAP_LOCKING` 和 `TRANSITIONING` 状态时返回 `attempt.to`，但 transition 只有 12ms，target 预览窗口极短
- `star-map` 的 DOM 结构有 `height: 100vh`，但 `host` 的样式是 `position: absolute; inset: 0; height: 100%`，如果 shell 高度不稳定（因为 `Presentation.visible` 只包含一个场景），`height: 100%` 可能计算异常

**用户描述的「star-map 先出来又消失」**：是因为 transition 完成后 `present('star-map')` 使 star-map 可见，但 `activateStableScene` 不执行（stableScenePlayers 为空），star-map 保持 poster 状态。如果用户继续滚动，star-map 的 `playForward` 在 `runScenePlayAttempt`（star-map → aod）时才触发，此时 star-map 会从头开始播放 reveal 动画，产生「先出来（poster）→ 又消失（开始 reveal）→ 再出来」的效果。

---

### 3. star-map → aod，aod 没有 1:1 复刻 main

**核实结果：✅ 成立（根因未解）**

- `star-map → aod` 是 `transition` 类型（`bottom-to-top-ink`），`TransitionSegmentPlayer` 只有 12ms
- AOD 的 `showPoster` 调用 `renderAodTransitionProgress(section, 0)` 和 `renderHandoffProgress(0)`，即 progress=0 的初始状态
- 运行时过渡不会调用 AOD 内部的 `aod-transition.js` 的 dissolve 动画，AOD 是以 poster 帧（progress=0）入场
- AOD 的 `playForward` 在 `runScenePlayAttempt`（aod → method-top）时触发，但此时 AOD 已经以 poster 状态显示，然后才开始播放视频
- 与 main 分支的「视频溶解入场」效果完全不同

---

### 4. belief（star-map 内部）80% 提前进场，不应盖住 aod 视频，文字应更高

**核实结果：⚠️ 部分成立（机制不同）**

- `starmap-scene-player.js` 的 `showPoster` 中 `setSourceVisible()` 设置 `copyWrap.style.opacity = ''`（默认 1），`sourceLayer.style.opacity = '1'`
- 这意味着 belief 文字在 star-map 的 poster 状态下**始终可见**，不是「80% 提前进场」而是「全程可见」
- star-map 在 `SceneRuntimeMvpVisualRegistry.js` 中**没有配置 milestones**，所以不会通过 early-copy 机制触发
- 用户描述的「belief 文字与 aod 视频重叠」可以通过根因解释：star-map → aod 的 transition 只有 12ms，star-map 瞬间切换到 aod。如果 star-map 的 canvas alpha 通道在边缘区域透出，或者 belief 文字的 z-index 高于 aod 的视频层，视觉上会出现重叠

**关于「文字应该更高一些」**：这是 CSS 布局问题，不在 scene-runtime 的范围内，但 `starmap-scene-player.js` 的 `buildSceneDom` 中 belief 文字位置由 `.starmap-scene__copy-wrap` 和 `.belief-copy-wrap` 的 CSS 控制。

### 5. figure2 第一阶段滚动时视频没播放，第二阶段没有做墨滴转场

**核实结果：✅ 成立（视频驱动方式未改）**

- `figure2-compound-scene-player.js` 中视频播放逻辑在 `startFigureVideos()` 中，由 `camera-expand` 阶段（2200ms 固定时长）触发
- `seekVideos()` 强制同步 `currentTime`，但视频是**时间驱动**的，不是 scroll-scrub
- 6566b28 没有修改 figure2 的视频驱动方式
- **关于墨滴转场**：`ink-sweep` 步骤的 `drawInkSweep()` 方法存在且工作正常（`figure2-compound-scene-player.js:913-963`），但 ink-sweep 步骤在 `PLAY_STEPS` 中定义，`playForward` 会按顺序执行各步骤。墨滴效果是在 figure2 **内部**渲染的，不是运行时级别的 transition。
- 用户说「第二阶段没有做墨滴转场」，可能是因为 `ink-sweep` 步骤的渲染被 `proofOverlay` 的 `handoffFade` 遮挡，或者 transition 太快（12ms）导致 ink-sweep 被跳过。

### 6. figure2 第二阶段结束后 → brand，「同野观幂做第四种…」整屏没出现，横向拱形 + 文案下到上水平墨滴 → brand 不可见

**核实结果：✅ 成立（部分改善但仍有 gap）**

6566b28 的改动：
- 新增了 `figure2-brand-bridge` DOM 结构（文案 + 拱形图）
- 新增 `renderBrandBridge()` 在 progress 0.86-1 时显示（opacity 0→1→0）
- 新增 `internalTarget` 处理逻辑：当 `present-brand` step 触发时，直接 `present('brand')` 而不走 `runTransitionAttempt`

**问题**：
- `renderBrandBridge` 的 opacity 在 progress 0.86-1 之间显示，但 `handoffFade` 在 `inkProgress` 0.9-1 时强制淡出 proof overlay。如果 brand bridge 的 z-index 不够高，或者被其他元素遮挡，文案可能不可见。
- `figure2 → brand` 的路由是 `scene-play-transition`，6566b28 让它在 `internalTarget` 匹配时直接 present brand，**跳过了运行时 transition**。这意味着 `bottom-to-top-ink` 的 runtime-level transition 不执行。
- 用户描述的「横拱 + 文案下到上水平墨滴 → brand 不明显」是因为 runtime transition 是 12ms 空壳，没有真正的墨滴动画。

### 7. brand → figure3，figure3 同时占了 from/to

**核实结果：✅ 成立（overlay 未清理 + 单 visible 限制）**

- `brand → figure3` 是 `transition` 类型（`bottom-to-top-ink`），`Presentation.visible` 只包含 `brand`
- `figure3-scene-player.js` 在 mount 时创建了 `transitionOverlay`，有 `position: fixed; inset: 0; z-index: 9999`
- 如果 overlay 没有被正确清理，figure3 的克隆内容会持续显示在最上层
- 但更重要的是：`Presentation.visible` 只包含 `brand`，`figure3` 被 `host.hidden = true` 隐藏。如果 `transitionOverlay` 没有被清理，就会出现「figure3 同时占了 from/to」的视觉效果。

**6566b28 没有修改 figure3 的 overlay 清理逻辑。**

### 8. 动画 80% services 文案提前入场，services 占了 figure3 画面，services 背景应为浅色

**核实结果：✅ 成立（背景色问题已解，但 early-copy 机制问题仍在）**

- `figure3-animation` 的 milestone 配置在 0.8 时 reveal `services`
- `services-scene-player.js` 的 support styles 将背景设为 `#ede4d2`（亮色）
- `SceneRuntimeDomShell.ensureShellStyles()` 中也有 `[data-scene-id="services"][data-scene-role="stable"]` 的样式设为 `#ede4d2`
- 但 early-copy 投影层（`[data-early-copy-projection]`）的样式是 `background: transparent`，所以 early-copy 状态下的 services 没有背景色，会透出 shell 的深色背景 `#07110e`
- **用户描述的「services 背景应该是浅色的」**：在 stable 状态下是正确的，但在 early-copy 状态下是错误的（透明透出深色背景）
- **用户描述的「services 占了 figure3 画面」**：`presentEarlyCopy` 将**整个 scene host** 标记为可见，early-copy 层显示的是 services 的完整 DOM，而 figure3 仍在播放。如果 figure3 的 video alpha 通道在边缘区域透出，services 的内容会叠加在 figure3 之上。

5. **belief 文字隐藏**（影响 Finding 4）
   - `starmap-scene-player.js` 的 `showPoster` 中设置 `copyWrap.style.opacity = '0'`
