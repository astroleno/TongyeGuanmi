## 加载和运行时

- 保留按章节加载模块。只在首页提前加载 Hero 手机背景；直接进入深层章节不再抢先下载首页背景。
- 可选图片预热按低优先级串行执行，按 URL 去重；最多持有 12 张、约 24 MiB 解码图像引用。失败可重试，单项超时会释放队列。
- Save-Data、2G/3G 或低带宽提示关闭可选预热。用户正在进入的章节及必须提前激活的视频仍然加载。
- 手机避免先加载一份 WebM/HEVC 再换成 packed-alpha；canvas 消费的媒体统一匿名跨域。
- 动画逐帧更新不再触发整页 React 渲染；可见性、章节边界、交互和错误仍同步发布。
- 星图保留原噪声数学结果，复用格点与像素缓冲。透明视频保留画面重绘证明，同时避免重复上传同一解码纹理。
- 修复正文原生滚动被外层容器截断，以及场景卸载、重新激活、回退时的资源所有权问题。
- 冷视频在首份数据到达后再准备精确端点；网络失败后的下一次显式准备会重新选择媒体源。
- 桌面显式准备优先接受视频帧回调；回调缺失时，必须已完成 seek、当前帧数据就绪、播放头在允许窗口内，并成功通过 canvas 解码读回才能放行。普通播放不走这条准备后备路径。隐藏章节保持隐藏。
- 未携带取消信号的桌面首帧准备会在外层构建截止之前取消，及时解除转场遮挡，避免迟到的准备结果覆盖已经恢复的页面。
- AOD 反向进入按末帧验收，避免已解码的末帧被首帧模式拒绝。
- 冷视频的真实时长到达后，等待者与 seek 同步更新目标；其他 loadeddata 监听器提前 seek 时，允许完成 seek 后继续首帧准备，避免已经解码仍等待到超时。
- 弱网首屏重绑画布时，短暂缺帧会在既有呈现截止时间内继续验证。没有放宽帧证明，也不重置截止时间；持续缺帧仍会明确失败。
- 精确端点准备的微小预寻址不再只依赖 seeked 事件；确认 seeking 已结束后继续回到目标帧，仍要求独立帧证明。取消或退役会清理检查计时器。

## 顺序、节奏和 vh / seek

顺序仍为：Hero → Pattern → Star Map → AOD → Method → Figure2 → Proof → Brand → Figure3 → Services → TTG → Lab → PH → Education → Crane → Contact。反向按同一相邻链返回。

`canonical-spine.ts`、`timings.ts` 的原始编排不变，包括 Hero 的 900 ms 动作 + 1800 ms 墨迹、Pattern 的两段 1800 ms 与中途手势停顿、TTG/PH 的播放及停留、Crane 原有时间轴。延长的是公网下载/解码准备期限，不是动画时长。

原架构是手势触发、按时间完成一段动画，并非 `scrollY / vh` 连续拖动整站视频。这次没有增加 Lenis，也没有将全部视频改为逐帧 seek；Figure3 等原有顺播继续保留。这样才能保持原动画停顿和先后关系。

- Hero、AOD、Figure2 的 seek 路径按素材 24/30 FPS 合并同帧目标。测试各采样 1001 个进度点、正反两个方向，误差不超过半个源帧；准备帧与端点仍用精确时间。
- 视口矩阵覆盖 390×664、390×844、1440×900、1440×1080，各检查 0%、25%、50%、75%、100% 及反向样本。
- TTG 的位移除以视口高度后保持相同 vh 比例；Crane 使用保留舞台高度，末端退出距离仍为 `1.38 × 0.82 × height`；Figure2 的 16:9 cover 坐标始终居中覆盖、镜头原点仍为 0.56。
- 公网预览 13 对上述四种视口实际播放 TTG → Lab，共采集 581 个样本，均覆盖完整 0 → 1。读取浏览器计算后的 transform，而不只检查写入的 CSS 变量：相对规范 vh 公式最大偏差为 0.005865 CSS px；视频目标进度误差小于 0.0001、目标时间误差小于 0.0001 秒，均为序列化精度量级。证据：`public13-vh-*.json`、`public13-vh-summary.json`。这是布局／目标时间对齐验证，不是视频解码零延迟或真实帧率测量。
- `video.currentTime` 与目标相同不能独立证明画面已呈现。端点验证保留视频帧回调或受约束的解码后备证明，packed-alpha 还需要 canvas 实际绘制证明。
