# 双端滚动实施与验证记录

日期：2026-10-10。基线提交：`966c507`；变更保留在当前工作区，未提交、推送或上线。

## 实施内容

- 桌面阅读：单一逐帧写入器，按时间步长追赶目标；普通输入 70ms、小幅密集输入 40ms。反向从可见位置重新计算；失焦、隐藏、导航、尺寸变化、减少动态效果和卸载均取消旧目标。浏览器量化 `scrollTop` 时仍可收敛。
- 删除正式输入链的每手势 1.05 屏阅读限额；边界交接仍读取实际位置并要求物理输入。补帧不产生故事输入，键盘和减少动态效果不走新追赶。
- 手机继续使用原生文档滚动。记录当前阅读节点、偏移、上下边缘及场景/提交身份，同场景尺寸恢复时验证并恢复；显式导航仍使用原落点。
- 修复手机恢复时误检查隐藏动画副本落点、旧布局宽度反馈及工具栏高度变化未恢复阅读偏移。短暂的浏览器滚动范围更新延迟沿原截止时间重试，不放宽画面证明或延长超时。
- 触摸过滤横向主导和多指手势，保留一次手势一次交接约束。
- 为遵守现有体积/架构预算，在受影响模块合并重复视口变量设置、选择器和滚动容器读取；没有提高预算、增加手机核心文件、安装依赖或改变内容及视觉设计。

最终接口采用内部帧调度，无外部 `frame()` 调用；书签以当前连接节点代替字符串锚点，仍校验根归属和提交身份。这是已批准方案中允许的现有接口内修复。

## 浏览器验证（首轮双端滚动）

来源：本地工作区与正式构建，现有发布回归及新增 `app/scripts/verify-smooth-scroll.mjs`。Ego 的帧回调受到约 1 秒节流，因此没有用该数据作性能结论；改用项目已安装浏览器测试能力完成必要视觉与时间验证，无额外安装。

- 手机发布回归：10 项通过、2 项按原测试约束跳过。Chromium 与 WebKit 各完成 60 次章节穿越，两轮完整正反向故事结束后资源拓扑和生命周期计数一致。Method/Proof 工具栏恢复及减少动态效果通过；Chromium 原生触摸的 Services → TTG → Lab → PH、Lab 边界首次触摸通过。两个 WebKit 跳过项需要 CDP 可信触摸输入，不算 WebKit 触摸通过。
- 桌面发布回归：所选 12 个场景最终均取得通过证据；其中 10 项首轮通过，旧异步阅读断言与旧媒体恢复断言校正后定向重跑通过。额外重跑的 Proof 阅读用例也通过。覆盖双引擎完整正向故事与关键反向路线、Chromium 菜单/历史、竞争导航、减少动态效果、慢依赖、Method 边界、长滚及媒体失败后的显式重试。
- 测试契约校正均有现有代码依据：手机 Figure2 distance 的 Ink 层原本为 55（保留前景拱门为 60），旧全链测试误写 70；媒体准备显式失败原本保留 star-map 并发出 `PREPARE_FAILED`，旧测试误要求超时并跳到 AOD。未修改对应层级或恢复业务逻辑。阅读测试则按本轮已批准设计取消 1.05 屏上限断言，改为完整长滚、无尾巴跳章及反向收敛。
- 轨迹脚本：双引擎 600px 滚轮输入均达到 250ms 内消化 95%、600ms 内收敛。手机 360×800、390×844、430×932、390×720，以及 844×390 横屏再回竖屏，均保持 stable/reading enabled、同一提交身份、无横向溢出；顶部/底部保持边缘，中段锚点偏移小于 1px。
- 已人工查看手机小屏、WebKit 工具栏高度变化及桌面阅读截图；没有以单纯 DOM 通过代替视觉检查。

10 秒测量环境：macOS / arm64，headless Chrome 155.0.8059.39、WebKit 26.5；不等于实体手机或显示器刷新率。首轮 Chrome 桌面 P95 16.8ms、手机稳态读取 P95 16.7ms；WebKit 两端约 34ms（约 30Hz），**没有达到 60Hz 的 P95≤20ms 目标**。WebKit 不提供本轮使用的 Long Tasks API，空列表不代表零长任务。

首轮 Chrome 捕获一次 66ms 长任务，且当时与静态检查并行；尚未归因，不能认定由滚动造成或认定无关。原记录保存在 `output/playwright/smooth-scroll/results-first.json`。不并行执行检查的复测通过全部功能断言：Chrome 两端 P95 均为 16.7ms，桌面 10 秒记录 601 帧、零长任务；WebKit 两端仍为 34ms。手机中段最大锚点偏移为 0.516px。复测未抹去首轮异常，也不据此宣称全设备性能通过。

可重复运行：先在本地启动正式构建预览，再执行 `SMOOTH_SCROLL_URL=http://127.0.0.1:4177 node app/scripts/verify-smooth-scroll.mjs`。原始轨迹、浏览器版本及截图位于 `output/playwright/smooth-scroll/`，该目录为本地忽略输出，不会自动随源码提交。

## iPhone 卡住反馈后的补充修复

用户路径：Proof 开场及「先跑通，再铺开」不能继续向下；锁屏后双向失效，但菜单可用；「场景 → 留学」仍不能滚，「方法 → 留学」可恢复。镜像确认手机访问 `tongye.me`，但控制接口拒绝点击/滚动，未能提取真机运行时。线上发布清单仍为 v55、来源提交 `ef69e06a`，相关源码与本地基线一致。

诊断不是单纯 FPS 问题，已取得两类独立浏览器证据：

1. 线上 v55 的场景/留学页面，在正文中部模拟隐藏再显示，进入 `presentation-landing-invalid` 故障，正文变为 inert、根 overflow 为 hidden。原校验要求动画副本的 `#services` / `#education`，实际阅读副本为 `#services-reading` / `#education-reading`；Method 同名 ID 掩盖了这类错误。现有本地书签/阅读副本校验修复可让页面保持原提交及阅读位置，新增场景、留学、Lab 的定向回归。
2. 本地 WebKit 中，即使 Shell 已 stable/reading enabled，深层 `:has()` 滚动规则仍出现“选择器匹配但 html 实际 overflow 为 hidden”。现在由 Shell 在绘制前直接同步 html 的阅读状态，并在退出/卸载时清理，CSS 不再从深层节点反推根滚动所有权。进一步用可实际产生原生滚动的 WebKit 输入作对照：根 overscroll 抑制下滚轮事件未被 preventDefault，但页面不动；恢复根原生 overscroll 行为后可滚动。边界切章仍由现有触摸仲裁、实际位置及交接令牌控制，不引入新的滚动写入器或惯性切章。

补充验证覆盖：

- 最终构建的双引擎综合脚本全部 39 条记录通过：新增 Services/Education/Proof 的模拟 visibility 与 BFCache 恢复，以及「场景 → 留学 → 方法 → 留学」菜单路径；检查正文位置、提交身份、html 实际 overflow/overscroll，而不只检查 Shell 状态。模拟生命周期不等于真实锁屏。
- 独立实际输入测试 8 次：Chromium 四个菜单节点在模拟恢复后接受可信协议触摸，实际滚动约 329–337px；WebKit 手机布局四个节点均接受原生滚轮默认行为，实际滚动 220px。WebKit 使用非 mobile 自动化上下文加粗指针/手机尺寸，不冒充 iOS 手指滑动。
- 已查看 Chromium 与 WebKit 留学正文实际滚动后的截图，无错误覆盖层；测试未记录页面运行错误。临时诊断证据在 `/tmp/tongye-lock-recovery/`，长期可重复的恢复/样式断言已加入原验证脚本。
- 最终构建定向发布回归 7 项通过：WebKit 的 Method 工具栏交接、Proof 保留拱门及减少动态效果 3 项；Chromium 的 Method/Proof 工具栏、Services → TTG → Lab → PH 触摸链和 Lab 首次边界交接 4 项。组合测试进程曾在 Chromium 项目结束后停滞，终止该自建进程后按项目单独重跑，不把停滞当作通过。

本轮使用前端排错技能要求的实际渲染/输入证据，发现并修正了此前仅靠程序化 scrollTop 和状态断言漏掉的 WebKit 问题；React 最佳实践保持单一 Shell 所有者与卸载清理。没有启动 agent、新增依赖、提高预算或修改内容/动画设计。

## 未完成的验收边界

- iPhone Air 已连接并收到用户实测反馈，但镜像控制接口不可用；修复版本尚未完成该手机复测。真实快滑、按住停止、反向、地址栏、锁屏/切后台及旋转仍待实机测试，Android 也未验证。
- 浏览器模拟和 WebKit 引擎不等同于真实 iOS；合成工具栏高度变化不等同于真实地址栏动画。
- 60/120Hz 单元步长证明算法一致性，不证明真实 120Hz 硬件性能。
- WebKit 本地约 30Hz，60Hz 指标未验证达标；首轮 Chrome 66ms 长任务未完成归因，复测没有再现。完整性能验收仍未关闭。
