## 整合模块与接口

1. **构建数据**：以 `app/build/seo-meta.ts` 维护站点实体、规范域名和页面元数据。静态页面、JSON-LD、sitemap 与 llms 由同一份内容数据派生，减少硬编码分叉。已有公司名、服务与方法以仓库已接受正文为来源。
2. **HTML 与结构化数据**：`seo-head.ts` 负责页面级 title、description、canonical、社交分享及 JSON-LD；`static-shell.ts` 继续生成首页正文。结构化数据描述必须在普通用户可见内容中有依据，不添加虚构评价、客户、资质、价格或效果保证。
3. **抓取资源**：真实提供 `/robots.txt`、`/sitemap.xml`、`/llms.txt` 与分享图片，返回正确类型。sitemap 只列公开规范页面；实验、测试、预览地址不作为公开内容入口。爬虫抓取政策不因增加专用规则而意外取消原有路径限制。
4. **服务器**：Nginx 明确公开页面、真实静态资源和不存在路径的行为，消除任意路径返回首页 200 的问题。首页、已有锚点和合法应用路由需要分别验收；预览隔离机制与正式发布身份保留。
5. **验证与发布**：构建检查与公开发布检查同时验证元数据、链接目标、资源类型和 HTTP 状态，不能只检查响应里含有品牌名。既有性能门槛与认证要求不放宽。

## 验收标准

- 普通访问与关闭 JavaScript 均可读取完整公开正文、页内锚点与联系入口。
- 公开页面返回 200；不存在页面返回 404；应重定向的地址返回明确重定向；爬虫资源不再回退成首页 HTML。
- JSON-LD 可解析、实体与链接可对应，标题及描述与可见内容一致，无重复 canonical 或被误设的 noindex。
- sitemap 内每个地址为可访问规范页，llms 的链接全部存在；分享图片真实可读且尺寸元数据准确。
- 首页动画、两端完整流程、原有资源与体积上限继续通过；新增静态页不拉取首页视频或动画模块。
- 分别记录 AITDK 实际结果、源码/构建验证、HTTP 检查与浏览器验证；工具未执行的项目不写为通过。
- 搜索收录、排名与 AI 引用属于发布后的外部结果，不能由本地测试或插件评分保证。
