# Animated Navigation Transition Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将首屏标题“同野观幂”的仪式感自然收束成轻量顶部导航，让首屏转场前后形成同一套排版系统：大字从品牌标题归位为导航结构，转场后页面进入更轻、更可浏览的状态。

**Design Principle:** 不是把“同 / 野 / 观 / 幂”硬拆成四个菜单，而是让标题字形参与导航生成：部分字归位为品牌标识，部分字作为运动锚点引出真实导航项。最终导航语义仍然是 `方法 / 企业 / 场景 / 教育 / 联系`。

**Tech Stack:** Existing static site, Vanilla ES Modules, GSAP + ScrollTrigger CDN, current hero title chars, fixed `.site-nav`, CSS transform/opacity only for layout motion. Optional ink texture uses existing in-repo WebGL text reveal primitives only after the FLIP path is working.

---

## Current Baseline

- `index.html` 已有 `.site-nav`，当前导航项为 `方法 / 场景 / 留学 / 联系`，CTA 为 `预约诊断`。
- 首屏标题已经拆成 `.hero-title-char`，当前结构适合做 FLIP-like transform。
- `js/sections/hero.js` 控制 hero intro、title intro、nav reveal、manifesto reveal。
- `js/ui/reveal.js` 负责普通 `.reveal` 入场和 nav active 状态。
- 当前 nav 在 hero 完成后才显露，首屏标题和导航之间没有视觉因果关系。

## Target Experience

1. 首屏标题仍然完整出现：`同野观幂`。
2. 首屏第一视口不急着暴露完整导航，让标题和山水/人物层级先完成仪式感。
3. 用户明确滚动后，在首屏后段到第二屏进入前的转场窗口内，四个标题字轻微解组。
4. 标题字沿稳定路径向顶部导航区域收束。
5. 左上形成小品牌标识 `同野观幂` 或单字 mark。
6. 顶部真实导航项淡入：`方法 / 企业 / 场景 / 教育 / 联系`。
7. 转场完成后，导航常驻、轻量、不抢后续内容的主视觉。
8. `prefers-reduced-motion` 下直接显示常驻导航，不执行飞字动画。

## Taste Decision: First Screen Or Second Screen

Use a **late-first-screen morph that completes before the second content screen becomes dominant**.

- Do not morph immediately on first paint. The brand title needs a readable, still moment; otherwise the navigation feels like it is stealing the hero's entrance.
- Do not wait until the second screen is already visible. By then the page has changed context, and the navigation appears as a late UI overlay rather than something generated by the title.
- Best timing: title intro completes, user scrolls with intent, hero begins its scene transition, then the title resolves into nav before the post-hero content asks for scanning/clicking.
- In review language: first viewport is for ceremony, the transition window is for system formation, the second screen should receive a finished navigation system.

This keeps motion intensity around a controlled `6/10`: memorable enough for the brand, but not a second hero competing with the content.

## Non-Goals

- 不做中文 glyph path morph。
- 不引入 MorphSVG 或新商业插件。
- 不把四个字永久当成四个菜单。
- 不延长 loader 或 hero intro 时长。
- 不改首屏核心水墨/人物/山水层级。
- 不直接引入 `reference/liquid_text.tsx` 的 React hook / Tailwind component。
- 不把整屏 `ink-scene-transition` 当作导航动画。

## Proposed Architecture

新增一个独立 UI 模块：

```txt
js/ui/title-nav-morph.js
```

Public contract:

```js
export function initTitleNavMorph({
  root = document.documentElement,
  body = document.body,
  reduceMotion = false,
  heroSelector = '.hero-wrap',
  progressMode = 'hero-transition',
  titleCharSelector = '.hero-title-char',
  navSelector = '.site-nav',
  navLabelSelector = '.nav-links a, .nav-cta, .brand-text',
  inkTexture = false
} = {}) {}
```

Ownership rules:

- `initTitleNavMorph()` owns `.site-nav` visibility, label opacity, motion glyph proxies, pointer events, and final interactive state.
- `initLayeredHero()` continues to own hero layers, video, manifesto, method preview, star field, and scene ink transitions.
- `initLayeredHero()` must stop mutating `.site-nav` when title-nav morph is enabled. Use an explicit option such as `manageNavReveal: false`.
- `js/ui/reveal.js` keeps section reveal and nav active state only; it must not set global nav visibility.

Progress rules:

- Use one progress source for the morph. Prefer the hero transition window already represented by scene transition progress (`rawHeroScroll`, `transitionStartRange`, `transitionRange`, or the equivalent `--hero-transition-progress` semantics).
- Avoid creating a visually independent timeline that drifts away from the existing ink/scene transition.
- Measurements can be refreshed with `ScrollTrigger.refresh()`, resize, and `document.fonts.ready`, but scroll-linked updates must remain transform/opacity/filter only.

CSS/markup contract:

```html
<span class="hero-title-char" data-title-morph-source="brand-1">同</span>
<span class="hero-title-char" data-title-morph-source="brand-2">野</span>
<span class="hero-title-char" data-title-morph-source="nav-1">观</span>
<span class="hero-title-char" data-title-morph-source="nav-2">幂</span>
```

Navigation placeholders:

```html
<span class="nav-morph-target" data-title-morph-target="brand"></span>
<span class="nav-morph-target" data-title-morph-target="method"></span>
<span class="nav-morph-target" data-title-morph-target="enterprise"></span>
<span class="nav-morph-target" data-title-morph-target="scenario"></span>
<span class="nav-morph-target" data-title-morph-target="education"></span>
<span class="nav-morph-target" data-title-morph-target="contact"></span>
<span class="nav-morph-target" data-title-morph-target="cta"></span>
```

The placeholders can be visually hidden layout anchors; final readable labels fade in separately.

Implementation note:

- Use motion proxy elements for the flying glyphs instead of physically moving the original title spans out of their heading flow. The original `.hero-title-char` remains the semantic/visual source and can fade out during the handoff.
- The four title chars do not map one-to-one to all nav labels. They act as typographic seeds: `同/野` bias toward the brand, `观/幂` bias toward the nav cluster. Final labels are readable anchors, not transformed glyphs.
- Optional texture path: existing `createInkTextReveal()` may be adapted later for a nav-label reveal, but first version should not depend on it. If used, expose a manual progress/render API or trigger it only for the final label reveal; do not run a free `requestAnimationFrame` loop during scroll.
- `reference/liquid_text.tsx` remains reference-only. Its useful idea is the `blur + opacity + threshold` texture, not its React component structure or looping timing model.
